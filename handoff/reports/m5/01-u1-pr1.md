## Deviations from the plan
1. **`Vocabulary.genericTokens` added (additive, D-28).** D-28 tests whether a sub-directory name "is not a generic token". The planned `nonStemTokens` field (generic tokens plus naming-suffix keys) cannot answer that once a configuration adds a naming suffix that is not generic. With the default vocabularies the two sets are equal.
2. **`inferredModuleKey` throws `InvalidIdentifierError`** when a stem is empty or contains `%`, `#`, `~` or `/`. The plan only states that stems never contain these characters; the throw enforces it instead of producing ambiguous ids.
3. **Plan defect: D-28 can break that rule.** A sub-directory stem is `sStem(asciiLower(s))` of a directory name, so a folder like `c#` gives a stem with `#`. IR.md now lists sub-directory stems among the stem forms and says "a sub-directory whose name contains one gives no stem". U3 has to implement that (see below).
4. **Smaller choices, all within the plan's types:**
   - `DEFAULT_INFERENCE_CONFIGURATION` has a narrower type than planned, with its inner sections fully required.
   - `roleLayers` never stores `null`, because an absent role already means "no layer".
   - Conventional tiers are numbered consecutively, so empty or repeated tiers do not leave gaps.
   - `settings.ts` also exports `MODULE_INFERENCE_METHOD` and `LAYER_INFERENCE_METHOD` (not from `index.ts`).
   - `nameParts(".eslintrc")` gives head `""` and qualifier `eslintrc`, matching the IR's `extensionOf`.
   - `pluralize` appends lower-case letters but keeps the case of a replaced `y`: `SKU` → `SKUs`, `CATEGORY` → `CATEGORIES`.
5. **Lint block is slightly stricter than listed.** The locale methods are banned on any member access, not only calls. Each import violation is reported twice, because the plan asks for both the base rule and its TypeScript version.
