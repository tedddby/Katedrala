# tangled-architecture

`corner-shop`, an online shop backend organized by feature directory that has grown without boundaries:
every feature reaches into the internals of the others. It is the "big ball of mud" counterpart to
`layered-architecture` and `clean-architecture`.

```text
src/
├── cart/        cart.ts  cart-repository.ts  cart-service.ts  cart-stats.ts  abandonment.ts
├── catalog/     index.ts  product.ts  product-service.ts  pricing.ts  recommendations.ts
├── checkout/    checkout-service.ts  order.ts  order-history.ts  payment.ts  receipts.ts
├── customers/   customer.ts  customer-service.ts  loyalty.ts  addresses.ts  segments.ts
├── inventory/   stock-level.ts  stock-service.ts  reservations.ts  warehouses.ts  subscribers.ts
├── lib/         db.ts  events.ts  money.ts          (shared helpers; import nothing internal)
└── main.ts      demo flow and a reminder job
```

25 files in the five feature directories, extensionless imports (`moduleResolution: "Bundler"`).

## How it is tangled

- 18 of the 20 possible directed dependencies between feature directories exist (only
  `customers -> catalog` and `inventory -> cart` are missing). All five feature directories form a single
  directory-level strongly connected component; `src/` (main.ts) and `src/lib/` are outside it.
- File-level cycles (over all import kinds), each crossing directory boundaries:
  - `cart/cart-service.ts -> checkout/checkout-service.ts -> customers/customer-service.ts -> cart/cart-service.ts`,
    plus the back edge `checkout-service -> cart-service` (runtime cycle);
  - `catalog/product-service.ts <-> inventory/stock-service.ts` (runtime cycle);
  - `checkout/order.ts <-> customers/customer.ts` (both edges `import type`: a type-only cycle);
  - `customers/addresses.ts -> inventory/warehouses.ts` (value) and back (`import type`): disappears when
    type-only imports are ignored.
- `customers/customer-service.ts` loads `checkout/order-history.ts` with a dynamic `import()` "to work
  around a circular import", a typical symptom; the static cycle through `cart-service` remains.
- `catalog/index.ts` is a barrel (`export *`), imported as `"../catalog"` and `"./catalog"` (directory index
  resolution).
- `main.ts` imports `./inventory/subscribers` for its side effects (event handler registration).

## Other cases

- `checkout/payment.ts` imports types from `../generated/payment-provider`, generated by an npm script
  into `src/generated/`, which is git-ignored (`.gitignore`) and absent: an **unresolved** import, not an
  external.
- External: `node:events` only.

## Expected conclusions

- 32 files (29 TypeScript sources, `package.json`, `tsconfig.json`, `.gitignore`); 94 imports; one unresolved
  import; four file-level cycles, two of which remain when type-only imports are ignored.
- Directory cycles: exactly one strongly connected component, `{src/cart, src/catalog, src/checkout,
  src/customers, src/inventory}` (directory = directory directly containing a file).
- High coupling: every feature directory both depends on and is depended on by at least three other
  feature directories; Katedrala should report the cycles and the coupled cluster as anomalies, and infer
  no clean layering.
